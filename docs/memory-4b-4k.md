# 4B 内存：8.8GB → 0.5–1.25GB

## 结论

不是聊天记录，也不是岸的记忆库。  
是 `llama-server` 的 **host batch buffer**。

把 4B 从：

```text
-c 8192 -b 2048 -ub 512
```

改成：

```text
-c 4096 -b 512 -ub 128
```

后：

| 指标 | 旧 8K / b2048 | 新 4K / b512 |
|---|---:|---:|
| `VmRSS` 空闲 | **8,812,624 kB** | **512,324 kB** |
| `RssAnon` | 8,537,144 kB | 224,124 kB |
| `RssFile` | 173,808 kB | 199,972 kB |
| `Pss` | 8,722,320 kB | 382,319 kB |
| 系统 available | 2.2Gi | **9.8Gi** |
| 显存 | 3,830 MiB | 3,595 MiB |
| 生成速度 | ~67 t/s | **~71.5 t/s** |

## 用起来之后

| 场景 | RSS |
|---|---:|
| 空闲 | 512MB |
| 3 条短请求后 | 838MB |
| 1565 token 长 prompt 后 | 853MB |
| 8765 普通聊天后 | 1.14GB |
| 8765 记忆硬路由后 | 1.25GB |

没有回到 8GB。  
之前连发 3 条短请求，RSS 只涨了约 100KB，也不是“聊一句漏一点”。

## 为什么

旧参数里 `-b 2048` 是逻辑 batch。  
4B 在 prompt processing 时会为这个 batch 准备 host 侧工作区；8K context 又把这个工作区撑大。模型权重在显存里，但工作台摆在了内存里。

`RssFile` 只有 174MB，说明不是模型文件缓存；  
`RssAnon` 8.5GB，才是真占用的匿名内存。

## 现在

- `serve.sh` 的 `4b` 默认已改为：`CTX=4096 BATCH=512 UB=128`
- `small` 仍是 1.5B / 8K
- `big` 仍是 7B R1 / 4K
- 8099：4B，4K，健康
- 8765：岸，`model=true`
- 记忆题实测仍正常：
  > 你又翻旧账。它前后不一致：第206轮说“记得猪猪”（×5）；第260轮说“没听说过猪猪”（×5）

## 代价

- 上下文从 8K 降到 4K。
- 对岸够用：system + recent 4 + 记忆卡，远没到 4K。
- 如果以后要喂长文，再单独开 8K / 小 batch 测一次；不要直接回到 `-b 2048`。

## 备注

zram swap 里仍有约 2.3GB 旧页，是系统其他进程的；  
`available` 已经回到 9.6–9.8GB，不需要现在动 swap。
